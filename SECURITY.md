# Security Policy

## Supported versions

Security fixes are provided for the latest released version of PrazyCron.

## Reporting a vulnerability

Do not publish vulnerabilities, secrets, private crontabs, or privilege-escalation details in a public issue. Use GitHub's private vulnerability reporting feature for the repository:

https://github.com/Prazynka/prazycron/security/advisories/new

Include the affected version, Linux distribution, reproduction steps, security impact, and any proposed mitigation. Please allow reasonable time for investigation before public disclosure.

## Scope notes

PrazyCron edits scheduling configuration and can request administrative authorization. A report is especially useful when it involves bypassing confirmation, modifying a source without the expected authorization, unsafe temporary files, command injection, credential exposure, or incorrect file ownership or permissions.
